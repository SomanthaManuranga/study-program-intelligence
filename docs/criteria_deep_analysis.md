# Evaluation criteria: deep-analysis layer for the argument (fixed before building)

Task (Soma, 31 Oct 2026): build the deep-analysis additions now - robustness and benchmarking analyses with current
industry techniques - so the project can make strong, defensible arguments for why a new programme would attract
(new) students to OTH. Git handling stays with Soma; the work lands as files in the repository. The pre-registered
criteria, thresholds, weights and scores stay untouched; everything new is additive evidence around the existing
three-level answer.

Planned additions (each: analysis module -> generated report -> evidence synthesis; limitations stated in place):
data-quality gate; capture-model rerun harness with a reproduction gate; specification-curve (multiverse) analysis of
the capture/viability model and of the Monte Carlo ranking (with seed, concentration and weight diagnostics); a
Gamma-Poisson shrinkage model over the published comparable intakes; a required-capture-share benchmark against
competitor pools; an embedding-based cannibalisation sensitivity; demand corridors from the rolling-origin backtest
errors; and a professor-facing argument brief that maps every claim to its evidence, strength and counterargument.

| # | Criterion | Target |
|---|---|---|
| D1 | Additive only: no pre-registered criterion, threshold, weight, score or existing generated result changes; new code only writes new files (plus pipeline step registration) | regression: existing outputs reproduce; key-number verbatim check stays clean |
| D2 | Reproduction gate: the rerun harness reproduces the pre-registered central results exactly (cyber gross 21 / 39 / 75, net new 15.3 / 32.0 / 64.4, shares (a) 14-27 %; robotics gross 14.9 / 28.7 / 55.3) before any variant is computed | automated test passes |
| D3 | Every new number is generated by code into reports/; each module states method, assumptions and limitations in its report header | no hand-typed results in the synthesis beyond quoted generated values |
| D4 | Framing: new results are sensitivities, robustness checks or benchmarks AROUND the pre-registered answer, never a replacement; wherever a new technique disagrees, both readings are shown | spot check of every conclusion sentence |
| D5 | Tests: each module gets a logic test on constructed data plus the reproduction gate; the full suite passes (known environment failures of this machine excepted: data/raw and streamlit absent) | pytest |
| D6 | The argument brief maps every claim to source doc, strength and the strongest counterargument with the honest answer; no claim without a number or a stated assumption | brief complete for both decision levels |
| D7 | Data-quality gate: schema, completeness and cross-table consistency checks pass on every consumed table | analysis.data_quality exits clean |

Iterate: fix failures and re-run, at most 3 rounds; if a criterion still fails, stop and report; never loosen a
criterion. Done when D1-D7 pass and the argument brief stands.
